# HT08 / MeloBuds Pro notes

**Role:** device notes (research/informative). Marketing items are hardware
context, not protocol evidence; open items must not be invented.

Hardware (marketing / reviews, not protocol):

- Bluetooth 5.3, A2DP / AVRCP / HFP
- SBC, AAC, LDAC, Hi-Res Wireless
- Hybrid / adaptive ANC, transparency with multiple levels
- 12 mm drivers, 6 mics
- Wear detection, game mode, multipoint, EQ, touch

Protocol (public opcodes we implement):

- Battery, firmware, ANC scenes, transparency levels, game mode, EQ v2, keys, wear, sleep, find chime

Transport evidence (issue #50):

- Direct observation on the test unit (`84:AC:60:62:69:DA`, Linux Mint 22.3,
  BlueZ 5.72): BlueZ caches `00001101` (Serial Port Profile) for the earbuds
  and never resolves the vendor GATT service `0000a001`; while connected for
  A2DP audio the BLE identity is asleep (no advertisement observed), and the
  earbuds auto-reconnect audio aggressively.
- Independent Jieli/QCY reverse-engineering projects (references in issue #50)
  report the control protocol as Jieli RCSP over SPP/RFCOMM carrying the same
  `0xFF` framing implemented here.
- An SPP/RFCOMM transport (`native/crates/qcy-transport/src/rfcomm.rs`) is
  implemented behind the `Transport` contract with deterministic tests; the
  write policy is enforced unchanged and unknown devices stay read-only.
