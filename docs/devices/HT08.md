# HT08 / MeloBuds Pro notes

**Role:** device notes (research/informative). Marketing items are hardware
context, not protocol evidence; open items must not be invented.

Hardware (marketing / reviews, not protocol):

- Bluetooth 5.3, A2DP / AVRCP / HFP
- SBC, AAC, LDAC, Hi-Res Wireless
- Hybrid / adaptive ANC, transparency with multiple levels
- 12 mm drivers, 6 mics
- Wear detection, game mode, multipoint, EQ, touch

Protocol (public opcodes we implement):

- Battery, firmware, ANC scenes, transparency levels, game mode, EQ v2, keys, wear, sleep, find chime

Transport evidence (issues #50, #52 — live sessions 2026-08-27):

- The test unit exposes **two identities**: BR/EDR audio `84:AC:60:62:69:DA`
  (A2DP/HFP/AVRCP + SPP `00001101` "COM5" channel 1) and a BLE control
  identity `C4:AC:60:62:69:DB` advertising manufacturer company ID `0x521C`
  (QCY), `AddressType=random`. The vendor GATT service `0000a001` **is**
  exposed by BlueZ on the LE identity; the original #50 premise (GATT absent,
  SPP required) was falsified — the earlier scans only looked at the audio
  MAC.
- Confirmed on live hardware over BLE GATT (no root): battery char `00000008`
  returns live `[L|R|Case]` levels, version char `00000007` returns
  `020004020004`, and ANC writes to char `00001001` (write-without-response)
  execute with audible effect and notify ACKs on `00001002` (see ANC note
  below). LE control and BR/EDR audio coexist simultaneously.
- ANC on HT08 is opcode **0x17 with a 3-byte `[mode, subScene, noiseValue]`
  payload**, not 0x0C. Hardware-confirmed payloads: off `(2,0,0)`,
  indoor/ANC `(1,1,2)`, transparency `(3,2,4)` (device ACKs `(3,2,0)`).
  Touch-sensor changes produced `(1,3,2)` (noisy) and `(2,0,0)` (off).
  The full mode table was individually confirmed by firmware ACK:
  commuting `(1,2,2)`, noisy `(1,3,2)`, wind `(1,4,2)` (ACK `(1,4,0)`),
  adaptive `(1,5,2)` (ACK `(1,5,0)`, announced by voice prompt); cross-checked
  against OpenQCY (MeloBuds Pro). Live 0x0C writes were silently ignored (no ACK, no effect);
  the ledger demotes 0x0C to experimental accordingly.
- Bootstrap/reachability: the control identity advertises connectable
  ADV_IND during normal use. The intermittent connection failures were
  host-side: an active HFP/SCO session on the BR/EDR link blocks LE
  connection initiation on this Intel controller (`le-connection-abort-by-local`,
  no `LE Create Connection` issued). With HFP released (card on A2DP),
  `Connect()` succeeds in the advertisement window; `Device1.Pair()`
  re-bonds the identity cheaply if the bond was lost. A resident LE control
  session with background discovery and an HFP preflight is therefore the
  implementation model (details in #52).
- SPP channel 1 on HT08 is a byte-ACK bridge only (`07 1e XX <echo> 03 YY 01
  ZZ`, `ZZ = 256-(len+1)`); it acknowledges frames but executes nothing
  (ANC writes had no effect even worn). Channels 4/5 accept RFCOMM connects
  and stay silent. The SPP/RFCOMM backend
  (`native/crates/qcy-transport/src/rfcomm.rs`, PR #51) remains as a generic
  transport for models whose evidence points to SPP; it is not the HT08 path.
